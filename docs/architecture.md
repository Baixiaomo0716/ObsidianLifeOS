# LifeOS 实施架构契约

契约版本1.2；2026-10-08修订；十类字段已补齐，主录入采用模板笔记。
依据：[PRD v1.5](../PRD-v1.0.md)、[数据规范](data-schema.md)、[验收计划](test-plan.md)。
替代1.0实体模型；[旧架构](history/contract-1.0/architecture.md)仅历史参考。

## 1. 产品与分层

首期为桌面/移动Obsidian插件，TypeScript+React+esbuild；依赖版本及最低宿主版本由DEV-003锁定并验证。P1日记、记账、待办、项目；P2阅读、影视、演出、旅行及游戏；P3知识；P4另评估Web/PWA。

界面src/ui调用应用src/services；领域src/domain负责纯规则；src/ports提供笔记、附件、操作日志、时钟、标识端口；src/adapters/obsidian只用移动兼容公开API；src/index负责可重建索引；src/settings分设备偏好与Vault业务配置。业务层不依赖DOM、Node、Electron或桌面文件路径。

十类独立业务实体为日记、记账、阅读、影视、游戏、演出、旅行、知识、待办、项目；字段与枚举使用拼音，详见数据契约。取消旧共用作品、独立经历、独立地点模型，旧文件仍保留，不自动合并或删除。首期记账仅人民币收入/支出，无账户、退款、转账、多币种和账户余额。

## 2. 文件与目录

Markdown/YAML、附件和系统业务配置是权威，缓存仅查询，不回写覆盖文件。业务根默认LifeOS/，可配置。新版模块目录为00_系统/、10_日记/、20_记账/、30_阅读/、40_影视/、45_游戏/、50_演出/、60_旅行/、80_知识/、81_待办/、82_项目/、90_附件/、99_回收与冲突/。
目录映射不重叠，只索引管理范围；系统、回收、冲突不参与统计。旧目录不自动移动。
配置、附件元信息、操作日志持久化字段也用拼音；技术文件名/API名称无需改成拼音。

内容字段作为YAML字符串保存，不与自由正文双写。日记neirong最多500 Unicode码点（包括空格、换行和标点）；自由正文不受此限制，不被表单覆盖。大段字符串用合法YAML多行编码器，DEV-006验证换行和特殊字符。

## 3. 安全读写与幂等

编辑时保存完整原文及内容版本，提交回调核对当前原文，发生变化暂停写入，提供重载或带新biaoshi的副本。不能只用gengxinshijian或修改时间做版本判断。仅改表单拥有字段，保留未知属性值类型和未编辑正文；YAML排版不保证字节不变。非法YAML、未知结构版本、重复标识只读并报告。

端口最低语义：创建、读取（原文/版本/实体）、预期版本更新、回收、恢复。错误区分校验、冲突、不存在、IO及不支持版本，界面不能将错误包装成成功。公开API由DEV-006证明符合版本保护。
官方Vault.process保护同宿主读改写，但不是分布式锁；修改时不能依赖陈旧缓存。[Vault文档](https://docs.obsidian.md/Plugins/Vault)。Frontmatter/活动正文优先遵循公开API建议；若不能同时保障版本检查与内容保护，可采用受保护文本变更并测试证明。[插件清单](https://docs.obsidian.md/oo/plugin)。

一次提交生成操作UUID和实体UUID；失败重试沿用同一操作、实体和请求指纹，不同请求不得复用。已保存同目标返回已有结果，不再新建。00_系统/operations/日志记录步骤和逐项失败，可重启恢复；外来未完成操作不得未经核对自动接管。无跨设备锁或跨文件原子事务承诺。

## 4. 关系、待办与项目

日记guanlian多选十类，切换类型保留选择、标识去重、禁止自身。无目标先新建保存，再附加关系，再返回日记。附加失败保留已建实体和原选择，只重试关系；取消创建无实体。

待办guanlian中的项目标识是归属权威，最多一个项目；项目daiban是反查的只读列表，不在两份文件双写。关闭/取消/归档项目禁止新归属，已有待办仍可操作。项目完成比例从有效待办计算，取消排除、归档保留，无任务未知；全部完成不自动结束项目。

项目完成先显示未完成待办，显式保留/取消/移出，逐项更新并记录失败，核对后最后完成项目。失败不提前写项目完成，可恢复已成功步骤，不承诺整体回滚。取消/归档项目不自动改待办；重开恢复jinxingzhong并清管理标记。被引用项目先解除引用才可删除；普通缺失关联保留提示，不级联删除。

## 5. 附件与同步

上传真实复制到90_附件/项目/<项目标识>/，成功后附加shangchuanwenjian；目标名加附件UUID保留扩展名。默认20MiB，可配置，DEV-002按实际服务限制确认。多文件逐项检查/复制/元信息/关联，失败可单项恢复，成功文件不覆盖；元信息记录原名、字节数、类型、导入时间。

所有路径为Vault相对路径，正斜杠。标准化后拒绝绝对路径、盘符、穿越、越出根目录。文件来源路径不成为持久引用。移出项目列表只解除引用；物理删除需明确操作且没有其他引用。尚未同步到本机显示不可用，不能假称可打开。

只选一个实际文件同步机制，P1不做自有云端和同步队列。反馈区分本地保存、同步未知、失败/冲突；没有可靠状态时提示“同步状态请在Obsidian中查看”。同步不是备份，独立恢复演练必须通过。手机没有桌面Node/Electron环境，模拟器不能代替真机。[移动开发](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development)。

## 6. 查询和界面

按biaoshi定位，路径可变；事件处理新增/修改/删除/重命名，批量合并，索引扫描分批可取消。重复标识所有争议记录不计正常统计，完整性修复后重建。

首页仅七个行动模块的jinxingzhong项，读取阅读zhuangtai及其他实体jindu，排除取消/归档/回收/冲突，标识去重；游戏实现后接入，未实现模块不假装能保存。计数与集中查看共用查询。
名称筛选只对有mingcheng实体；日记/记账显示生成标题但不额外存名称。日期查询按各实体实际日期，不将上映时间当观看时间。日记今天自动汇总与显式关系分区，记账关系不重复计费。
取消旧重读/重看/消费次数、知识结构化来源、旅行预算/实际费用及独立地点统计，新增需求须另立契约。

首页/记录/回看/设置导航不变。所有框架按容器空间限制高度，标题/保存按钮固定，内容区纵向滚动；320px起不横溢，末项、键盘焦点和手机键盘下按钮可达，滚动保留选择。原型像素值只作参考。
