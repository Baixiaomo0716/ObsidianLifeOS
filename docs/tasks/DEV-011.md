# DEV-011：数据完整性与回收恢复

2026-10-09；状态：工程完成，新命令与回收弹窗待宿主补验。用户反馈DEV-010索引命令执行通过，仅记录该命令，不推断所有文件事件已逐项实测。手机暂缓。

## 交付

integrity-check.ts重建后报告重复标识、同日重复日记、非法格式/结构版本、缺失或回收/争议关联目标、多个项目归属、缺失项目附件。不修改原文件或自动删除引用。

trash-store.ts列出回收快照，捕获版本生成动作，交由OperationService执行持久化日志与完整原文检查。MD和JSON保留原路径、标识、未知属性、正文和关系。回收采用yihuishou/huishoushijian逻辑标记，不移动或永久删除文件、附件；恢复设为false并清除回收时间。正常查询排除回收项，恢复后原关系重新可查；目标仍缺失时报告，不伪造目标。

entities.ts与validation.ts将既有记账回收标记扩展为十类可选系统元信息，结构版本保持2，不增加业务录入字段。非法标记报告而不静默修正。entity-index.ts提供快照读取，同日有效重复日记均排除正常查询并报告；回收其中一篇后另一篇可重新查询。

main.ts与styles.css加入完整性弹窗、回收列表与恢复按钮、当前记录回收/恢复命令，长列表框内滚动。列表恢复支持不便在原生编辑器打开的JSON行。启用插件不自动回收或恢复；99_回收与冲突/仍存冲突材料，逻辑墓碑留业务根，保持同步路径。

项目有任何记录引用时拒绝回收，包括回收记录中的关联；扫描无法确认数据安全时暂停项目回收。项目daiban为派生字段，不作为归属权威。检查基于最新本地扫描，但没有跨文件/跨设备原子锁，外部并发新增引用仍需后续完整性检查。

冲突、未知版本或缺身份记录需先修复，不能强行回收。准备后原文变化拒绝写入；响应失败提示未确认完成，需核对日志或重新读记录，底层同操作标识可恢复。当前没有永久删除或自动清空功能。
