# DEV-016：多类型关联选择器

2026-10-10；契约1.5，业务文件格式不变。工程已完成，实际桌面交互待确认。

## 使用入口

LifeOS→回看，日记和待办行的“编辑关联”；笔记校验侧栏的“编辑关联”；命令“LifeOS：编辑当前日记或待办的关联”。源笔记必须字段有效、身份唯一、没有回收。按照目前字段契约，仅日记和待办编辑关联；十类实体均可作为目标，其他类型的原生字段不被额外扩展。

选择类型后搜索标题、正文或标签，勾选多条，切换类型保留原选择。结果分页50条，结果与已选区分别限制高度并滚动；自身不出现在候选中。已选区展示停用类型的历史引用，缺失/回收/争议目标明确提示，允许保留或显式移除。新选择仅来自启用类型。

待办最多关联一个项目，不允许新增归属到已完成、取消或归档项目，既有归属可以保留。按ID忽略大小写去重，不按标题判重。取消选择器不保存；移除已选项后保存仅改源笔记的关联，不修改或删除目标。正反向查询继续复用DEV-015索引。

## 保存与恢复

准备请求时复制原始快照和选择，重建索引并比较完整原文；实际首次提交再次核对目标。通过已有操作日志服务保存，仅设置guanlian兼容字段，编码到中文文件的隐藏系统区；正文、未知属性和身份保留，更新时间按底层规则更新。原文冲突不覆盖，关闭后重开选择器取得新快照。

快速重复点击有同步提交锁；同一准备请求的并发执行共享Promise。未确认回执时锁定选择，重试沿用同一操作标识和请求；已完成日志可恢复回执，即使目标后续变化，也不重放保存。执行开始后关闭弹窗不撤销已经提交的保存，完成或失败通过宿主提示报告，不重新打开弹窗。卸载关闭弹窗、卸载React根并释放索引订阅，旧代回调不弹提示。

目标检查与源笔记提交不是跨文件原子事务；提交后其他设备仍可能回收目标，既有完整性检查会提示缺失引用，不删除源关联。

“无结果新建并自动返回原日记”依照任务清单留在DEV-019接入；本项不伪造新建成功或自动关联。
