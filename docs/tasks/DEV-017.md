# DEV-017：附件导入与引用保护

2026-10-10；基于契约1.5。工程已完成，实际桌面文件选择和打开体验待确认；手机继续暂缓。

## 已实现

新增二进制文件端口、Obsidian公开Vault.readBinary/createBinary适配器、浏览器SHA-256摘要、AttachmentStore和项目附件引用服务。插件不使用Node、Electron或桌面绝对路径。

来源为浏览器File/AttachmentSource，不持久保存设备原路径。准备时检查配置的每文件大小限制（默认20MiB），复制读取的字节，实际大小不符拒绝。路径包含项目UUID、原文件名的安全部分、附件UUID和原扩展名；同名文件生成独立目标，不覆盖已有文件。穿越、绝对路径、目录分隔符和无效项目身份拒绝；Windows不允许的显示名字符仅在目标名替换，原名仍保留。

附件复制目录为LifeOS/90_附件/项目/<项目标识>/。导入元信息位于LifeOS/00_系统/附件/<附件标识>.json，独立结构版本1，字段：标识、项目标识、名称、字节数、类型、导入时间、路径、摘要、结构版本。先保存不可变导入意图，再独占复制二进制文件，最后重读并检查长度与SHA-256。存在元信息不等于复制成功，read/verifyPath只有真实字节核对通过才返回有效附件。

未知已有目标不认领，即使内容相同也不覆盖。已有导入意图可用于同请求重试；元信息或字节变化暂停，保留原件。完成后释放缓存字节，再执行只核对，不悄悄重建后来删除的文件。服务重新实例化可使用prepare(source, projectId, resumeId)恢复原导入意图，要求重新选择的文件与原名、大小、类型和摘要全部匹配；没有原文件时不凭元信息伪造成功。

项目附件引用只设置隐藏的上传文件路径列表，不恢复原生属性栏的上传文件字段，不改正文、身份或未知属性。新增引用必须有元信息和已验证的真实副本，提交前再次核对；项目原文改变停止，操作日志支持相同请求的重复回执恢复。保留历史缺失引用或显式解除引用均不删除文件。多个项目可共享同一已验证附件，取消一个项目的引用不影响其他项目。此模块不提供物理删除接口。

## 可体验入口

打开一篇字段有效的项目笔记，运行命令“LifeOS：导入附件到当前项目”。选择多个文件，逐个导入或导入全部。每行显示复制/关联进度和失败原因，失败文件单独重试，后续文件继续执行；同项快速重复点击不创建重复请求。关联保存未确认时复用已复制附件及同一日志请求，不重新复制。

关闭弹窗会停止尚未开始的排队项；已开始项仍可能完成，完成/失败通过宿主提示报告，不重新打开窗口。卸载时关闭窗口、停止后续操作，旧代回调不提示。这个入口用于验证公共导入流程；完整项目详情的附件列表、打开与移出交互仍由DEV-027完成。

## 边界与验证

字节复制与项目引用不是跨文件原子事务；关联失败时保留附件及元信息，避免删除共享或已复制资料。原文冲突需要重新读取项目后另行处理，重试不会强制覆盖；关闭/重启后的原导入恢复目前是服务接口，完整恢复入口在后续项目管理界面接入。同步状态未知，不宣称复制完成就已同步；尚未同步/被删除的真实文件核对失败。
