# LifeOS 数据契约

契约版本：1.2；修订日期：2026-10-08；新数据结构版本：2。
十类字段已补齐；录入改为模板创建普通笔记，原生编辑器填写属性，详见template-entry.md。
依据：[PRD v1.4](../PRD-v1.0.md)、[架构契约](architecture.md)。这是设计阶段修订，未运行数据迁移。

## 1. 命名、保存和通用字段

所有持久化字段名均使用小写、无声调、连续拼音，不使用英文缩写或下划线。枚举也使用拼音。界面显示中文。技术文件名、UUID标准、货币代码、日期时区标准和用户正文不受拼音命名约束。

每条记录一个UTF-8 Markdown文件，简单YAML属性用于结构化信息，自由正文继续保留。用户所列“内容”等字段以属性保存，不与自由正文双写；附件通过相对路径引用。可选值省略，不以0冒充未知。未知旧属性和未编辑正文保留。

| 中文 | 拼音字段 | 类型与规则 |
|---|---|---|
| 标识 | biaoshi | UUID v4字符串，全库唯一、不可变，不作为普通表单输入 |
| 实体 | shiti | 枚举：riji/jizhang/yuedu/yingshi/youxi/yanchu/lvxing/zhishi/daiban/xiangmu |
| 结构版本 | jiegoubanben | 正整数；新记录为2，未知版本只读 |
| 创建时间 | chuangjianshijian | 带偏移ISO 8601时间字符串，创建后不改 |
| 更新时间 | gengxinshijian | 带偏移ISO 8601时间字符串，实际修改成功才更新 |

日记、记账没有额外名称字段，列表标题由日期、收支和分类生成；其他实体使用各自mingcheng。系统字段必须保存，但不要求用户填写。

日期为带引号YYYY-MM-DD字符串；时间含偏移，初始业务时区Asia/Shanghai。纯日期不因换时区而改写。用户输入的未知日期省略，不伪造时间。

## 2. 进度、状态及派生字段

阅读字段名为zhuangtai；影视、演出、旅行、待办、项目字段名为jindu。两种字段的值均为weikaishi/jinxingzhong/yiwancheng，对应未开始/进行中/已完成，默认weikaishi；同一记录只能有适用的一个进度字段。游戏使用jindu，适用统一三状态。

系统管理字段也用拼音：wanchengshijian（完成时间）、yiquxiao（已取消，布尔默认false）、quxiaoshijian（取消时间）、yiguidang（已归档，布尔默认false），仅适用于进度实体。首次完成生成时间，重复完成保留；离开完成清除。取消和归档不是第四种进度，取消不计完成；普通切换进度不自动清理管理标记。撤销待办完成默认weikaishi；项目重新打开固定jinxingzhong并清除完成时间、取消及归档标记。

星期自动由日期推算，中文值星期一至星期日；星期一为首日。日记农历按Asia/Shanghai对应中国农历日期计算，存可读字符串（如二〇二六年八月廿八），正确识别闰月；不预写无法验证的具体农历日期。DEV-005选择支持范围明确的历法实现，测试已知节日和闰月；超出支持范围提示不可用，不猜测。修改日期同步重算星期/农历，旧文件不一致列出校验提示，不能静默改写正文。天气手工填写，首期不接天气接口。

## 3. 十类实体字段

除公共系统字段及适用管理字段外，不增加未要求的业务输入。下表“必填”指保存要求；默认或派生字段由软件补齐。

### 3.1 riji（日记）

| 中文 | 拼音字段 | 类型、要求和规则 |
|---|---|---|
| 日期 | riqi | 日期，必填；沿用一天一篇规则，重复创建打开已有 |
| 天气 | tianqi | 字符串，可选，手工填写 |
| 星期 | xingqi | 字符串，按riqi自动生成 |
| 农历 | nongli | 字符串，按riqi自动生成，范围限制明确 |
| 关联 | guanlian | UUID列表，默认[]，十类多选，按标识去重，禁止自己 |
| 内容 | neirong | 字符串，可选，最多500个Unicode码点；空格、标点、换行均计数 |

日期是已有必要字段，新增所列六项。内容计数不是UTF-16长度，表情按码点统计；前端计数和保存校验一致，超限拒绝，不截断。自由正文不套用500字限制，也不由neirong自动覆写。

### 3.2 jizhang（记账）

| 中文 | 拼音字段 | 类型、要求和规则 |
|---|---|---|
| 日期 | riqi | 日期，必填 |
| 星期 | xingqi | 自动从riqi生成 |
| 收入/支出 | shouzhi | shouru/zhichu，必填，默认zhichu |
| 分类 | fenlei | 非空字符串，必填，按收支维护分类选项，不再引用账户或分类实体ID |
| 标签 | biaoqian | 字符串列表，默认[]，去空去重 |
| 金额 | jine | 正安全整数，必填，单位人民币分；输入12.50保存1250 |

首期固定人民币，不新增币种输入。金额按十进制字符串解析，小数最多2位；12.501拒绝。禁止浮点乘法取整，金额与累计值检查安全整数边界。收入=sum(shouru)，支出=sum(zhichu)，结余=收入−支出，可为负；结余不是账户余额。移除账户、转账、退款、期初余额、多币种功能，不把旧记录自动变为收支。
分类按名称保存，重命名选项不自动改历史；可停用选项但历史仍显示。不同收支可同名分类，查询使用shouzhi+fenlei。

## 4. 系统配置、关系和迁移

系统配置与辅助记录键同样使用拼音。设置使用jiegoubanben、shiqu、mulu、fujianzuidadaxiao；分类设置使用shouzhi、fenlei、qiyong。取消账户和币种字典。
附件元信息：biaoshi、jiegoubanben、lujing、yuanmingcheng、zijieshu、meitileixing、daorushijian、caozuobiaoshi。
操作日志：biaoshi、jiegoubanben、caozuoleixing、qingqiuzhiwen、mubiaobiaoshi、shebeibiaoshi、buzhou、cuowu。这些不是第十一类实体。

guanlian以UUID引用；缺失目标保留并提示，普通记录不级联删除。项目有待办或其他引用时不能直接删除。索引反向关系不是权威文件。首页通过实体适用zhuangtai/jindu判断jinxingzhong，排除取消、归档、回收和冲突，每条仅一次。

旧结构版本1与新结构2不是改名即可兼容：work拆阅读/影视/游戏，experience和place取消独立实体，账户/退款数据无自动映射。旧文件默认保留只读并提供迁移报告；未知英文属性不删除。迁移必须备份、预览、显式执行及恢复验证。转账/退款不自动伪装成支出/收入；阅读页数不转换为字数；多次经历不静默合并成单时间。

旧拼音转换参考（仅迁移设计）：id→biaoshi，type→shiti，title→mingcheng（仅有名称的实体），schema_version→jiegoubanben，created_at→chuangjianshijian，updated_at→gengxinshijian；业务模型拆分必须人工核对，不能批量盲替。

## 6. 模板录入生效规则

当前主录入流程见[模板笔记录入](template-entry.md)和[十份模板源](../templates/README.md)。空属性是初稿占位，未填必填或系统字段时不计正式统计；完善校验后纳入。可选空值在规范化时省略，不能清空未知字段。原生笔记自动保存，校验错误只提示并排除正式统计，不强制删除或阻止宿主保存。
全部用户字段按属性展示；长文本保持属性存储，源模式可编辑多行，不另双写正文。didian统一列表，避免同名属性在Vault共享类型冲突。项目daiban虽显示为属性，归属权威仍是待办guanlian，插件重算刷新。biaoqian是普通列表，不等于原生tags。
