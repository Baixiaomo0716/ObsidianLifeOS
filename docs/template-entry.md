# 混合录入方案：九类模板与记账表单

日期：2026-10-09；契约1.4。当前需求覆盖旧“十类全部模板”方案，详细记账方案见[独立数据表](ledger-table.md)。

## 录入与查询

日记、阅读、影视、游戏、演出、旅行、知识、待办、项目：选择类别→调用对应模板新建.md→原生属性填写→自动保存→LifeOS校验和刷新。
记账：选择记账→专用表单→日期/自动星期/收支/分类/标签/元金额→校验后保存数据表行→返回表格或原关联笔记；不生成MD、不调用模板。
首页、回看、搜索和日记关联通过统一索引读取两种数据来源。记账详情用表单，其余类型用原生笔记。

## 保留的属性限制

简介、评价及知识内容等仍展示的长文本属性继续按文本保存，源模式可编辑YAML多行；日记直接写正文，待办/项目的旧内容隐藏保留，不再显示为属性。地点同名统一列表；标签为普通列表，不自动等于原生tags；进度文本校验中文三状态。
关联以稳定标识关联九类笔记或记账行，辅助侧栏显示名称，选择/新建仍需插件。项目待办是反查的派生属性，权威在待办关联；上传路径需真实复制，不能仅填路径当上传成功。
核心Templates提供标题/日期变量，不生成UUID或农历，LifeOS创建命令补系统字段。九份模板源系统字段为空，初稿缺必填或错误暂不计统计，不损坏用户原文。记账表单则保存前拒绝无效金额，并保留输入。

## 优缺点

| 模式 | 优点 | 代价 |
|---|---|---|
| 记账表单+数据表 | 金额按元输入、分类选择、校验清楚，收支筛选汇总方便 | 专用页面与JSON行适配需开发，原生笔记编辑器不能直接管理行 |
| 九类MD模板 | 保留原生写作和长期可读性，减少业务表单 | 属性限制和手工错误仍需校验 |
| 混合统一查询 | 日记仍可关联账本，首页统计连贯 | 标识索引须处理笔记/数据表两种来源及冲突/回收 |
| Vault内行文件 | 不需服务器，不覆盖单一整表文件 | 实际同步和独立恢复仍须验收，不是分布式数据库事务 |
