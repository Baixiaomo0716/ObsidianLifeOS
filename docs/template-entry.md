# 模板笔记录入方案

修订日期：2026-10-08。用户已确认以十类模板新建普通笔记，直接填写笔记属性；替代独立业务表单作为主录入入口。字段依旧拼音。模板见[模板目录](../templates/README.md)。

## 流程

首页新建→选择日记/记账/阅读/影视/游戏/演出/旅行/知识/待办/项目→创建对应目录的Markdown笔记→调用模板→打开Obsidian原生编辑器填写属性。首页、搜索、回看、统计仍由LifeOS读取笔记，原生编辑器是主要编辑入口。
新增游戏字段：mingcheng、leixing、jianjie、faxingshijian（日期）、pingjia、jindu（统一三状态），不增加时长或通关次数。

## 模板与插件分工

核心Templates可以插入属性并替换标题/日期/时间变量，但不能仅凭模板完成唯一标识、农历、500字校验、项目反向查询、上传或可靠统计。LifeOS创建命令负责生成biaoshi、时间、目录、日记去重，再打开笔记；文件保存事件负责校验和刷新索引。原生编辑器自动保存，无表单“提交”步骤，错误只能提示并使该笔记暂不计统计，不能拦截所有手工写入或删改原文。
模板源提供空系统值，普通Templates手动调用后需LifeOS补全并验证；不是可独立运行的插件。未填写必填值、标识未生成或校验失败记录保留草稿，不计正常统计，首页显示待完善数量与入口。

## 所有字段属性化的约束

按用户要求，简介、评价、内容也保留为属性，不默认迁移到正文。Obsidian属性适合短文本，不渲染Markdown，长段落在原生属性面板填写体验较差；可在源模式编辑YAML多行文本。推荐未来允许这些长文本在正文分区编辑，但需用户接受后另改契约，不能双写两套内容。
属性名在同一Vault共享类型：didian统一列表（演出单地点也为单元素列表），leixing统一文本，评分为数字，日期统一日期。
biaoqian是普通列表，不自动等于Obsidian原生tags；保留拼音要求，LifeOS提供标签查询，不承诺宿主标签面板识别。
jindu/zhuangtai原生为文本，模板给默认值但不是受限下拉，LifeOS校验拼音枚举并可提供快捷状态命令。
guanlian继续保存稳定标识，原生属性显示标识不如双链直观；LifeOS关系侧栏显示名称并提供选择/新建返回。双链可另外写正文，不双写成第二份关系权威。
项目daiban属性作为可见派生列表，由LifeOS刷新，用户编辑不作为归属权威；创建/移出实际改待办guanlian。这属于只读语义，原生编辑器不能彻底禁止用户手工改，插件提示并从权威重算。
shangchuanwenjian属性是文件路径列表，不是上传控件；仍需“添加项目文件”命令完成复制、元信息、引用保护。
当前jine仍按分存储，原生属性旁需说明“单位：分”；LifeOS显示为元。模板直接填写1250表示12.50元，填12.50会校验失败，不能无声误记金额。若想直接填元，需要单独变更金额契约，不能将旧分值自动改解释。

## 优缺点

| 维度 | 优点 | 代价与补救 |
|---|---|---|
| 开发 | 复用原生笔记编辑，减少十套表单 | 校验、动态字段、关联、附件与统计仍要开发 |
| 数据 | 普通Markdown/YAML，可自由编辑、长期可读 | 手工改错更容易，需要草稿/错误列表与无损保护 |
| 多端 | 复用桌面手机编辑器和文件同步 | 模板和插件配置也要部署，真实同步仍须验收 |
| 写作 | 属性和正文同页，直接双链和附件 | 全部属性化导致长文本不便，属性不渲染Markdown |
| 查询 | 统一字段方便首页聚合与筛选 | 拼音自定义标签无原生tags能力，UUID关系需辅助界面 |
| 流程 | 新建后即写，降低页面跳转 | 自动保存不会等待业务完成，校验失败不能当正式记录 |

建议采用“原生模板笔记作为录入+LifeOS提供校验、关系、文件和汇总”。产品目标仍是人生管理系统；十模板降低编辑界面工作量，但不等同于十模板即可完成产品。
