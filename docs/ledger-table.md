# 独立记账数据表与表单方案

日期：2026-10-09；契约1.4，PRD1.7。记账单独管理数据表，其他九类使用Markdown笔记。DEV-006已实现JSON行基础读写、版本保护和逻辑回收恢复，DEV-007已实现操作日志、幂等恢复和冲突副本；数据表页面与表单仍待DEV-022/024，实际同步尚未验收。

## 1. 页面和填写

记账入口打开专用表单，不创建Markdown，不调用笔记模板。
用户填写日期、收入/支出、分类、标签、金额；星期根据日期自动生成，只读。金额输入单位元，例如12.50，保存金额=1250分，界面继续显示12.50元。
日期默认今日，收支默认支出；分类和金额必填，标签可多选。保存前校验，提交失败保留输入，重复点击/失败重试同操作仅生成一行。
记账数据表显示日期、星期、收支、分类、标签、金额；支持新增、查看、编辑、回收/恢复、搜索、日期/收支/分类/标签筛选、排序和分页。收入/支出/结余汇总可进入筛选明细。仍仅人民币收支，无账户、转账或退款。

## 2. 表结构与物理存储

逻辑表名记账，一条记账对应一行；列为公共系统字段标识、实体、结构版本、创建时间、更新时间和业务列日期、星期、收支、分类、标签、金额。名称与值沿用数据契约。
优先在Vault内管理本地逻辑数据表，保持无需独立服务器的多端目标。物理权威文件为20_记账/shuju/<标识>.json，每文件一行，表格由读取行文件生成；不是Markdown笔记，也不是把整个账本数组反复覆盖到同一文件。表格与查询缓存可重建，缓存不能作为唯一账本。JSON行是内部格式，用户通过表单编辑。

系统描述20_记账/biaojiegou.json记录表名、存储格式版本和列定义，键使用拼音，不属于额外业务实体。描述文件不决定实际统计数值。
当前选择JSON行文件而非共享SQLite二进制库，是为了沿用Vault文件同步、移动兼容和单条冲突恢复边界。若用户需要真正SQL数据库，须另外验证移动运行时、同步/服务端与备份方案，不直接同步同一共享数据库文件。数据表是产品交互与逻辑模型，物理存储设计可在DEV-002/006验证后修订。

回收行保留标识，写系统字段已回收=true、回收时间；恢复设置false并清回收时间。统计排除回收行。采用逻辑墓碑避免单纯移动文件时其他设备恢复出重复活动行；墓碑保留和物理清理必须明确备份/同步后处理，当前不自动清理。同步本身仍不能保证分布式事务。

## 3. 混合读写和关联

NoteStore负责九类Markdown；LedgerStore负责JSON行，提供创建、读取、预期版本更新、回收/恢复。统一实体索引按标识和实体定位，并记录数据来源；记账详情打开表单，其他类型打开原生笔记。笔记关系关联可引用记账行标识，不要求目标存在.md文件。
日记关联新记账→打开记账表单→保存行成功→附加日记关联→返回原笔记。跨存储附加失败保留记账行及原选择，只重试关系，不重复记账。解除日记关联不删除行；回收关联行保留关系并提示，恢复后能重新定位。

行更新校验完整内容版本，不仅更新时间。JSON非法、未知版本或重复标识只读报告；未知列保留。相同行多端冲突保留双方、统计提示不完整，不自动选最新。不同ID行分别保存降低整表竞争，但不能宣称解决所有同步冲突。路径标准化、根目录边界和幂等与原契约相同。

## 4. 导出、备份和迁移

提供CSV导出，标题列使用中文，金额按元导出并说明单位，标签以JSON数组字符串保存、正确转义；可另导出原始JSON保留系统标识/分单位。CSV是导出结果，不是第二权威，默认不承诺CSV回写导入。
独立备份包含记账行、表描述、九类笔记、附件、关系和操作日志；空Vault恢复后重建统一索引及账本汇总。
旧记账MD及模板仅历史资料，不自动删除或迁移。后续迁移预览、备份、明确执行，保留标识并防止MD/JSON重复计入；不合格旧记录人工核对。原记账模板已转为历史文件，不出现在新建入口。
