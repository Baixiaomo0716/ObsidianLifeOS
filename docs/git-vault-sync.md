## 4. 手动优先与冲突恢复

初期关闭无人值守自动同步，先手动验证：编辑前同步远程；编辑结束后保存本地变更、提交，再与远程合并并推送。Git客户端流程可能包含先提交再拉取；不能在脏工作区盲目覆盖。编辑前检查失败或冲突时停止跨设备继续修改。
发现冲突，暂停自动推送；保留本地、共同基线和远程版本，逐项查看后人工解决，账本JSON先验证再纳入统计。不同标识行通常可并存；同一行不得按最新时间静默取舍。Git文本自动合并无冲突也可能破坏YAML/业务规则，因此拉取后仍需完整性检查。
不使用强制推送、丢弃全部更改或硬重置处理业务冲突。LifeOS当前没有可靠Git状态接口，界面仅保证本地保存；同步成功以客户端推送/拉取结果及另一端实际文件为证据。

可选的原生Git JSON冲突策略示例位于docs/examples/vault-sync.gitattributes，使用merge=binary让双方修改同一JSON文件时保留未解决冲突，避免把行文本直接拼成无效JSON。[Git属性说明](https://git-scm.com/docs/gitattributes)。手机工具是否支持该属性及保留双方版本必须实测；支持不明不得声称保护已经生效，也不自动部署到手机。

## 5. 附件和备份

产品默认单文件20MiB（20,971,520字节）保留；官方Sync套餐5MB/200MB不适用当前Git方案。Git本身版本号不能证明远程主机单文件/推送/仓库容量上限。最终限制取产品默认与已核实远程限制的较小值，并实际测试接近上限的文件；远程尚未确认，不能保证附件跨端可用。
首期不默认启用Git LFS；手机工具是否支持LFS和认证需另验，不能用只下载到指针文件当附件同步成功。
Git历史提供恢复线索，但独立备份仍需Vault外目标；本地备份不推到同一Git仓库。恢复含账本JSON、笔记、关联、附件及系统状态。
