# LifeOS 人生管理系统产品需求文档

## 0. 文档说明

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.3，首页只展示进行中事项，卡片固定框架及溢出滚动；沿用当前文件名 |
| 文档状态 | 待评审，尚未实现或实测 |

| 首期形态 | 支持桌面和移动端的 Obsidian 插件 |
| 长期形态 | 在实际需要时增加独立网页 / PWA，与插件共享数据规范和业务规则 |
| 服务对象 | 单个用户在多台设备上使用 |
| 本期十大方向 | 日记、记账、阅读、影视、游戏、演出、旅游、知识、待办、项目 |

本文为新方案的产品与开发基线。旧 `PRD.md`、旧附录及 `架构与原型图.html` 保留供历史对照，其内容未同步至本版本，不能直接作为本版验收依据。本文的文档版本与下文产品发布版本分别管理。

本版替代旧方案中的月度记账对象数组，采用一笔交易一个文件；待办和项目纳入首期基础能力，天气、游戏化不纳入首期强制范围。历史数据迁移必须单独预览、验证后执行。

## 1. 背景与目标

### 1.1 用户需求

用户希望将日常记录、消费经历和知识积累统一保存，并通过易用的前端完成录入和回看。数据需要长期可读，能够在手机和电脑之间延续使用，并允许继续在 Obsidian 中自由写作。

### 1.2 产品目标

1. 降低记录成本：通过表单保存，不要求用户手写 YAML 或维护目录。
2. 建立生活关联：日记、作品、活动、支出、知识、待办和项目能够相互连接。
3. 支持长期回看：按日期、类型、状态、标签检索，并提供明确口径的统计。
4. 保持数据自主：核心数据为 Markdown、YAML 和普通附件，卸载插件后仍可阅读。
5. 支持个人多端使用：桌面和移动端使用同一套内容规范，通过一种选定的文件同步方式交换数据。
6. 保留扩展空间：业务规则与宿主读写分离，后续可接入网页。
7. 支持行动闭环：从记录产生待办，将待办组织成项目，完成后回顾结果与产出。

### 1.3 首期不包含

- 多人共享账本、实时共同编辑、团队权限。
- 独立网页、服务端账号、远程 API、原生独立 App。
- 银行账户直连、自动支付抓取、专业会计、投资管理。
- 自动爬取作品信息、AI 摘要、天气、经验值系统。
- 团队任务指派、复杂项目依赖、甘特图、自动循环待办、系统推送提醒。
- 自建文件同步引擎、保证跨设备实时一致性。

以上功能可另立需求，不作为首期完成条件。

## 2. 核心场景

| 编号 | 场景 | 期望结果 |
|---|---|---|
| S01 | 手机快速记一笔支出 | 输入金额和分类即可保存，未同步时有清晰提示 |
| S02 | 晚上写日记 | 查看当天关联记录，正文可以在原生编辑器继续写 |
| S03 | 读完一本书 | 更新书籍状态，新增完成记录，关联读后感 |
| S04 | 再次观看同一电影 | 复用作品档案，新增观看记录，不复制作品 |
| S05 | 参加演出或旅行 | 保存活动档案，将票务、支出、日记和照片关联 |
| S06 | 将摘录整理成知识 | 保存来源和自己的理解，链接作品及相关概念 |
| S07 | 月末回顾 | 查看支出、完成阅读、观看和活动统计，能进入明细核对 |
| S08 | 从电脑切换到手机 | 同步完成后浏览和编辑记录，发生冲突时保留双方内容 |
| S09 | 随手记录一件要做的事 | 只填标题即可进入收集箱，稍后补日期、优先级和项目 |
| S10 | 推进一个项目 | 定义目标和完成标准，拆解待办，查看进展及关联产出 |
| S11 | 每日安排与复盘 | 首页查看今天和逾期待办，完成后在当天日记页面回看 |

## 3. 产品原则

- **文件是权威数据**：索引、汇总和缓存均可从文件重建。
- **对象与经历分开**：作品档案描述对象，经历记录描述某次发生的行为。
- **身份与路径分开**：稳定 ID 用于关联，标题或文件名变化不改变身份。
- **保护自由写作**：更新表单字段不得覆盖用户正文和未知属性。
- **先保存，再同步**：本地保存与远端传播分别反馈。
- **冲突保留双方**：不得通过静默覆盖解决无法确定的冲突。
- **格式可验证**：字段类型、枚举、统计口径和升级规则明确。
- **移动端优先录入**：常用操作不依赖鼠标悬停和桌面专属能力。
- **同步与备份分开**：同步不能替代独立历史备份。

## 4. 信息架构与页面

### 4.1 顶层导航

| 页面 | 职责 | 主要内容 |
|---|---|---|
| 首页 | 了解当下并快速进入 | 日期、今日待办、进行中事项、今日记录、今日支出、快速记录、最近动态 |
| 记录 | 创建内容 | 日记、记账、新建待办置顶，其余模块按启用情况展示 |
| 回看 | 浏览、编辑与统计 | 时间轴、模块筛选、搜索、列表、详情、模块统计；包含待办和项目管理视图 |
| 设置 | 管理使用偏好 | 路径、模块、账户、分类、附件、索引、校验、同步说明 |

移动端前三项作为主导航，设置从固定按钮进入。十个模块作为内容分类，不要求十个顶层导航项。“回看”除历史内容外，也承载未完成待办和活跃项目的管理。

### 4.2 首页

- 显示当天日期、日记入口、本地已索引的当天记录数量与支出。
- 快速操作：写日记、记支出、新建待办；其他操作按启用模块出现。
- 今日待办展示未完成且计划日期为今天或截止日期为今天的任务；逾期任务单独分组，同一任务只出现一次。
- 每组默认最多显示 5 条，可直接完成、撤销完成或进入完整待办视图。
- 首页“进行中事项”仅汇总待办、项目、阅读、影视、游戏、演出、旅游中 status 为 in_progress 的全部条目；未开始与已完成均不进入此集合。
- 按目标或截止日期、更新时间排序，展示类型、标题、状态并可进入详情；完整集合可分批加载，不能截断后隐藏剩余条目。计数与“集中查看”采用相同过滤口径。
- 汇总以实体 ID 去重；作品按档案汇总，不将每次消费经历重复计为一项。取消、回收或明确归档的实体不进入首页集合。
- 项目显示任务进度；其他类型不编造完成百分比。更新状态后首页计数和集合即时重算。
- 最近动态默认显示最近 10 条，可进入完整列表。
- 无记录时显示操作引导，不用虚构数据填充。
- 不显示未接入的天气或统计卡片；关闭待办或项目模块时隐藏对应区块，保留已有数据。
- 统计标注数据更新时间；索引未完成时不显示误导性的零值。

### 4.3 表单与详情

- 必填字段清晰，错误定位到对应字段。
- 保存时禁用重复提交；保存成功后可打开详情或原始文件。
- 关闭有未保存修改的表单时提示保留或放弃。
- 详情显示结构化字段、正文预览、关联记录和原文件入口。
- 长文通过 Obsidian 原生编辑器编辑；首期不自建完整富文本编辑器。
- 删除默认进入可恢复的回收位置；永久删除另行确认。

### 4.4 搜索与回看

- 支持标题、正文、标签、类型、业务日期、状态筛选。
- 默认按业务日期倒序；可切换创建时间和更新时间。
- 时间轴按经历日期排列，不能把作品出版日期当作用户经历日期。
- 统计点击后进入对应筛选明细，保证数字可追溯。
- 无结果、加载、校验错误、关联缺失均有独立状态。

### 4.6 固定框架与滚动

- 所有内容卡片统一保留边框、内边距与固定高度；按卡片类型设置不同高度，不随记录数量无限增长。
- 卡片标题和关键操作固定，正文、列表放入独立内容区域；溢出使用纵向滚动条，不能直接裁掉不可见内容。
- 首页今日待办、最近动态、快速记录、进行中事项使用等高框架；列表、项目文档、日记关联内容、表单按各自用途配置高度。
- 表单的保存与取消固定在卡片底部，输入区超长可滚动；项目文件列表和多选关联列表同样在框内滚动。
- 整体应用框架固定，主导航和顶栏保持可见；手机底部导航固定在应用框架底部，主内容区单独滚动。
- 鼠标滚轮、触控滑动与键盘焦点移动均可访问全部内容；滚动不丢失选择、未保存输入或文件列表。
- 原型参考高度：桌面应用 900px、手机应用 780px；首页卡片 270px，一般内容卡片 340px，表单 510px。实现时按实际宿主可用高度适配，不要求真实手机页面高于屏幕。

### 4.5 待办与项目视图

- 待办提供收集箱、今天、逾期、全部及三个统一状态视图，可按项目、优先级筛选；取消项在独立管理视图查看，不作为第四种进度状态。
- 收集箱为未完成、无计划日期、无截止日期且未归属项目的任务。
- 待办列表默认按逾期、截止日期、优先级、创建时间排序；缺失日期排在有日期之后。
- 项目提供列表和详情；状态看板作为 P2 增强，不依赖拖拽才能修改状态。
- 项目详情包含目标、完成标准、状态、日期、关联待办、项目文件、产出和复盘正文。
- 从日记、作品、旅行或知识详情可创建关联待办；在项目内新建待办时自动填入 project_id。

## 5. 内容模型

### 5.1 实体与关系

| 实体 | 职责 | 典型关系 |
|---|---|---|
| 日记 | 某一天的叙述 | 当天经历、交易、知识 |
| 交易 | 一次收支或账户间转账 | 活动、作品经历、退款原交易 |
| 作品 | 一本书、一部影视作品、一款游戏 | 多次阅读、观看、游玩 |
| 经历 | 一次阅读、观看、游玩或活动参与 | 对象、日期、支出、感想 |
| 演出场次 | 一场具体演出 | 参与记录、场馆、票务 |
| 旅行 | 一次行程 | 地点、活动、日记、交易 |
| 地点 | 可复用的地点档案 | 多次旅行和活动 |
| 知识笔记 | 概念、方法、主题和理解 | 来源、作品、其他知识 |
| 待办 | 一项可完成的行动 | 可选所属项目、来源笔记、相关活动 |
| 项目 | 有目标和完成标准的一组行动 | 多个待办、知识产出、旅行、支出、复盘 |

结构化关系保存目标 ID；可读正文使用 Obsidian 双链。双链用于阅读，ID 用于程序关联。新增关联时不得自动改写用户手写正文。

### 5.2 通用字段

| 字段 | 类型 | 规则 |
|---|---|---|
| id | 字符串 | 全局唯一，创建后不变 |
| type | 枚举 | journal / transaction / work / experience / performance / trip / place / knowledge / task / project |
| title | 字符串 | 可编辑，文件名不作为身份 |
| schema_version | 整数 | 数据结构版本，与产品版本分开 |
| created_at | 时间字符串 | 包含时区偏移 |
| updated_at | 时间字符串 | 成功修改后更新 |
| date | 日期 | 按实体表示业务日期；无意义的实体可省略 |
| tags | 字符串列表 | 可为空 |
| related_ids | 字符串列表 | 通用补充关系，不替代专属关系字段 |

属性优先使用文本、数字、日期和简单列表，避免嵌套对象数组。专属字段沿用统一类型规则，同名字段不得在不同模块中采用不同数据类型。

### 5.3 统一进度状态

| 存储值 | 页面名称 | 含义 |
|---|---|---|
| not_started | 未开始 | 已建立档案或计划，尚未执行 |
| in_progress | 进行中 | 正在执行、阅读、观看、游玩或参与 |
| completed | 已完成 | 用户明确确认完成 |

- 待办、项目、阅读、影视、游戏、演出、旅游统一使用以上 status，默认 not_started；新建表单、列表筛选、详情均展示。
- 完成写入 completed_at；撤销完成默认回到 not_started 并清空完成时间，也可显式选择 in_progress。
- 取消使用独立 is_cancelled 布尔值及 cancelled_at，不增加第四种进度状态；归档使用 archived，不冒充完成。
- 演出场次进度与用户参与经历、作品档案状态与消费完成记录分别管理。修改档案状态不自动虚构观看次数、游玩时长或参加记录。
- 日记、知识、交易不强制加入进度状态。
- 旧值迁移：todo/planned → not_started，active/ongoing → in_progress，done/attended → completed；paused → not_started 并保留迁移说明，dropped/cancelled → not_started 加 is_cancelled。保留原始值和来源供核对，迁移须预览和备份。

## 6. 十大模块需求

### 6.1 日记

- 核心字段：date、mood（可选）、tags。
- 每天默认一篇日记；再次创建打开当天已有文件。
- 正文支持自由写作，不强制填写固定问答。
- 页面动态展示当天经历、交易、计划待办和当天完成任务；汇总不作为重复权威数据写入正文。
- “关联行动”升级为“关联内容”：允许手动关联其他日记、记账条目、待办、项目、阅读、影视、游戏、演出、旅游、知识，支持跨类型多选。
- 操作顺序：选择内容类型 → 搜索并多选已有项 → 确认关联；切换类型不清空已选项。
- 没有匹配项时，可新建该类型内容，保存成功后自动关联并回到原日记；之前已选项一并保留。取消新建则返回原选择状态。
- related_ids 保存显式关联，按 ID 去重，不允许关联自身；重复关联不会复制原实体。
- 解除关联只删除关系，不删除原记录。缺失目标显示提示，可解除或重新关联。
- 当天自动汇总与显式关联分区展示；关联账本条目不会生成第二笔交易，跨日期内容也可关联。
- 支持日历与时间轴浏览。
- 同一天出现多个日记文件时标记重复，由用户选择合并，不自动删除。

### 6.2 记账

- 一笔交易一个 Markdown 文件。
- 字段：kind、amount_minor、currency、account_id、category、date、备注及可选关联。
- kind：expense / income / transfer / refund。
- 金额为正整数最小货币单位，方向由 kind 决定；人民币 12.50 元保存为 1250 分。
- 支出和收入需要账户与分类；转账需要 source_account_id 和 target_account_id，两个账户不得相同。
- 首期转账只支持同币种账户；跨币种兑换另立需求。
- 退款必须关联原支出，币种相同；累计退款不得超过原支出。
- 退款按退款发生日期抵减净支出，历史消费日期保持不变。
- 总收入排除转账和退款；净支出为支出减退款；允许某月净支出为负。
- 不同币种分别统计，未提供明确汇率时不合并。
- 账户余额须基于明确的期初余额及全部交易计算；首期不宣称与银行实际余额一致。
- 分类和账户有稳定 ID；已被使用的账户可停用，不直接删除。
- 删除被退款引用的支出时阻止直接删除，提示先处理关联退款。
- 首期不包含账单导入；后续导入必须支持预览、外部交易 ID 去重和回滚。

### 6.3 阅读

- 书籍档案：作品类型 book、标题、作者、ISBN（可选）、封面、状态、个人评分。
- 档案状态统一为 not_started / in_progress / completed；弃读使用独立取消标记。
- 阅读经历：work_id、日期、动作、可选页码与时长、正文。
- 动作：start / progress / complete / reread_complete。
- 进度同时填写当前页和总页数时，当前页不得超过总页数。
- 已读本数按统计期内完成经历关联的不同 work_id 计数；重读次数另计。
- 摘录、读后感和知识笔记可分别关联书籍及阅读经历。

### 6.4 影视

- 作品档案：电影或剧集、标题、创作者、年份、封面、状态、个人评分。
- 观看经历：work_id、日期、观看动作、可选集数、短评。
- 同一作品允许多次观看记录。
- 影视档案使用统一三状态，重复观看作为经历另记。
- 电影完整观看计一次；剧集进度与整部完成分开保存，不能把每集观看都算成一部作品。
- 作品数量按不同作品 ID 计算，完整观看次数按完成经历计算。

### 6.5 游戏

- 档案：标题、平台、状态、封面、个人评分。
- 游玩经历：work_id、日期、duration_minutes（可选）、动作、心得。
- 时长使用非负整数分钟，缺失表示未记录，不等于零。
- 动作至少包括 play / complete；通关次数与游玩次数分开统计。
- 同一游戏不同平台的购买信息可后续扩展，首期不接入平台账号。
- 游戏档案使用统一三状态；完成状态不自动生成通关次数或时长。

### 6.6 演出

- 场次：标题、类型、艺人、开始时间、场馆或 place_id。
- 参与经历：performance_id、日期、参与状态、座位信息、观后感。
- 演出场次和参与经历的进度使用统一三状态；取消另设 is_cancelled。参加次数仅依据未取消且已完成的参与经历。
- 票根作为附件；票款以关联交易为准，不重复录入为第二笔支出。
- 参加场次统计排除取消和仅计划记录。

### 6.7 旅游

- 行程：标题、开始日期、结束日期、状态、地点 ID 列表、计划预算（可选）。
- 行程状态：not_started / in_progress / completed；取消另设 is_cancelled。
- 结束日期不得早于开始日期。
- 游记、照片、日记、经历和交易通过 trip_id 关联。
- 实际费用从关联交易计算，预算与实际费用分别展示。
- 首期提供列表和行程详情；地图及定位服务作为后续增强。

### 6.8 知识

- 字段：标题、知识类型、主题标签、来源 URL 或 source_ids。
- 类型：concept / method / excerpt / synthesis。
- 正文推荐包含来源内容、自己的理解和相关问题，允许自由组织。
- 可从作品经历创建知识笔记，自动带入来源 ID，不自动替用户生成理解。
- 首期提供搜索、主题筛选、关联笔记入口；关系图使用 Obsidian 原生能力。

### 6.9 待办

#### 基础字段与存储

- 一项待办一个 Markdown 文件，复用通用 ID 和版本规则；仅标题必填。
- 专属字段：status、priority、scheduled_date、due_date、project_id、source_ids、completed_at、cancelled_at。
- status：not_started / in_progress / completed，默认 not_started；取消另设 is_cancelled。
- priority：high / medium / low，默认 medium；日期和所属项目可为空。
- project_id 指向一个项目，一项待办最多归属一个项目；其他关系使用 related_ids。
- source_ids 保存产生待办的来源，例如日记、书籍、知识笔记；源文件删除时提示缺失，待办仍保留。
- 正文保存说明、执行记录和结果。首期不包含子任务层级、依赖关系或自动循环生成。

#### 状态与日期规则

- 点击完成设置 completed 与 completed_at；再次提交相同完成操作不得改变原完成时间。
- 撤销完成恢复 not_started 并清空 completed_at；取消设置 is_cancelled 与 cancelled_at，不计为完成。
- 恢复取消任务回到 not_started 并清空取消标记与取消时间；开始执行切换为 in_progress。
- completed 和已取消任务不进入今天、逾期及未完成计数。
- 日期使用用户设置的时区解释；逾期为 due_date 早于今天且任务未完成、未取消。
- scheduled_date 晚于 due_date 时阻止保存并提示；任一日期为空不做该项比较。
- 跨天后未完成任务保留原日期和原 ID，进入逾期或全部视图，不复制到下一天。
- 截止日期是计划信息；首期只提供页面内提示，不保证 Obsidian 关闭时的系统通知。

#### 权威状态与兼容边界

- YAML status 是系统待办状态的唯一权威来源，页面勾选写入该字段。
- 用户正文中的 Markdown checkbox 是自由笔记，首期不解析为独立受管待办，也不自动同步状态。
- 不宣称与 Tasks 插件自动互通；旧周文件 checkbox 迁移需显式生成任务文件，保留来源链接并去重。
- 待办完成数按当前 completed 状态、未取消及 completed_at 统计；撤销完成后从当前完成统计移除。首期不提供完整状态变更审计统计。

### 6.10 项目

#### 基础字段与页面

- 一个项目一个 Markdown 文件；标题、goal（目标）、completion_criteria（完成标准）必填。
- 专属字段：status、start_date、target_date、completed_at、archived、is_cancelled、output_ids、attachment_paths。
- status：not_started / in_progress / completed，默认 not_started；archived 和 is_cancelled 为独立布尔值，默认 false。
- goal 与 completion_criteria 为简短文本，详细方案和复盘写入正文。
- output_ids 指向项目产出，其他生活记录或交易通过 related_ids 关联；项目关联费用从交易计算。
- target_date 不得早于 start_date。未完成且未取消的项目超过目标日期时显示延期提示，不自动顺延日期。
- 首页“进行中事项”仅包含未归档、未取消且 in_progress 的项目；未开始、已完成和归档项目仍可在完整列表搜索和回看。

#### 进度与生命周期

- 关联任务由 task.project_id 反向查询，不在项目文件中重复维护任务 ID 数组。
- 进度为已完成任务数 / 非取消任务总数；没有有效任务时显示“暂无任务”，不显示 100%。
- 任务比例仅表示行动进度，不等同于项目目标是否达成。
- 项目完成由用户根据完成标准明确确认，写入 completed_at；全部任务完成不自动结束项目。
- 存在未完成任务时，完成项目需列出这些任务并要求用户选择继续保留、取消或移出项目；跨文件操作失败须可恢复重试。
- 修改项目进度、取消或归档项目不自动改变其待办状态；页面展示未完成任务提示，并提供显式批量处理。
- 在已完成、已取消或已归档项目中新增或挂入任务时阻止操作，提示先重新打开项目。
- 重新打开项目切换为 in_progress、清空 completed_at，并取消归档及取消标记；原产出和复盘保留。
- 项目有引用时不得直接删除；可归档，或先明确处理待办归属和其他引用再移入回收位置。
- 首期不包含成员指派、团队协作、资源排程、里程碑树和甘特图。

#### 项目文件

- 项目详情提供多文件上传入口；首期实现为从设备选择文件并复制到知识库附件目录，不依赖云服务。
- 默认保存到 `90_附件/项目/<project_id>/`，attachment_paths 保存相对路径列表；大小、类型、添加时间从文件和元信息读取，列表展示名称、大小、类型、时间与操作。
- 支持多选 PDF、Office 文档、文本、Markdown、图片等常见项目资料。单文件大小限制可配置，默认建议 20 MB，按实际同步服务限额验证。
- 保存文件成功后才建立项目关联；逐项显示处理中、成功、失败，失败可重试，不得把未写入的文件报告为成功。
- 同名文件采用不覆盖的唯一文件名；同批重复项提示跳过或作为新版本保存，不静默替换原文档。
- 列表支持打开原文件与移出项目；移出默认只解除引用，不删除磁盘文件，共享附件受引用保护。
- 处理文件名和路径，禁止写入配置附件根目录之外；同步后的桌面与手机均应可打开支持的文件。
- 原型仅展示文件选择和列表，实际文件保存、预览和多端同步仍须开发验收。

## 7. 存储与技术边界

### 7.1 默认目录

```text
LifeOS/
├── 00_系统/          配置、数据规范、账户和分类定义
├── 10_日记/
├── 20_记账/
├── 30_作品/          阅读、影视、游戏档案
├── 40_经历/          阅读、观看、游玩、演出参与等
├── 50_演出/
├── 60_旅游/
├── 70_地点/
├── 80_知识/
├── 81_待办/
├── 82_项目/
├── 90_附件/
└── 99_回收与冲突/
```

根目录和模块目录可配置。索引只管理该根目录内的系统实体，不擅自转换其他笔记。普通文件采用标题加短 ID 避免重名；日记按日期命名。业务日期用于展示，文件创建时间不能替代业务日期。

### 7.2 实现分层

| 层 | 职责 | 首期建议 |
|---|---|---|
| 界面层 | 表单、列表、详情和统计 | React + TypeScript，适配 Obsidian 宿主 |
| 业务层 | 校验、实体关系、统计、冲突判断 | 与 DOM、文件路径和宿主 API 解耦 |
| 存储适配层 | 查询与安全更新 | Obsidian 公开 Vault API |
| 索引层 | 搜索与统计缓存 | 首期内存索引及可重建缓存 |
| 权威存储 | 持久化内容 | Markdown + YAML + 附件 |

首期移动端不得依赖桌面 Node.js 文件系统接口。SQLite 可作为后续服务端索引选项，不作为首期移动插件依赖。

### 7.3 文件更新规则

- 修改前读取当前文件并检查打开表单时的内容版本。
- 版本变化时暂停写入并提供重新加载或保留为副本的选择。
- 仅更新本次修改的受管字段；保留未知属性和正文。
- 文件重命名、删除及外部编辑触发索引更新。
- 文件格式错误只标记并报告，不自动重写或清空。
- 全量索引可重建，不能以缓存覆盖文件。
- 删除和冲突副本排除在正常统计之外。
- 涉及多个文件的操作必须可重试；操作结果不完整时展示待修复状态。

## 8. 多端、离线和同步

### 8.1 首期方案

每台设备安装 Obsidian 和兼容的 LifeOS 插件，选定一种笔记库同步方式。优先评估官方 Sync，替代方式按实际设备兼容性验证；不得同时叠加多种机制同步同一笔记库。

单用户跨设备最终一致是本期目标，不保证跨设备事务或实时共同编辑。

### 8.2 状态反馈

- 本地写入完成：显示“已保存到本机”。
- 只有可验证同步结果时，才显示“已同步”。
- 无法获取同步服务状态时：显示“同步状态请在 Obsidian 中查看”，不能推断成功。
- 无网络仍允许本地创建和编辑；文件传播交由选定的同步服务。
- 首期插件不另建一套待上传队列，避免与文件同步服务重复负责。

### 8.3 冲突与幂等

- 每次创建使用稳定的操作 ID 和实体 ID，重复点击或重试不得产生第二条交易。
- 同设备文件更新采用受控读写；跨设备冲突由同步机制与后续校验共同发现。
- 内容版本检查不能完全阻止跨设备竞争，不宣称具备分布式锁。
- 检测重复 ID、同日重复日记、同步冲突文件和缺失关联。
- 无法识别的同步服务冲突仍依赖该服务提供的恢复工具；验收必须覆盖选定服务。
- 系统不自动覆盖争议版本，允许用户查看两份内容并选择合并。

### 8.4 备份与恢复

- 提供备份说明和数据目录定位入口。
- 用户设置独立于同步的版本备份；不把同步历史当作唯一恢复机制。
- 首期发布前完成一次真实备份恢复演练。
- schema 升级先备份、预览，再迁移；失败保留源文件和日志。

## 9. 附件与隐私

- 图片、票根和文档使用相对路径，移动端与桌面可解析。
- 删除笔记不立即删除共享附件；清理附件前展示引用情况。
- 原始视频和大型媒体不纳入首期自动管理，允许保存外部位置链接。
- 默认不上传笔记正文，不接入遥测或自动外部内容抓取。
- 新增联网功能须说明发送的数据与服务来源，并允许关闭。
- 首期不提供额外本地密码锁或加密，不能把普通 Vault 文件描述为已加密存储。
- 同步加密、终端访问保护和本地备份权限分别由选定环境管理。

## 10. 后续独立网页 / PWA

满足浏览器随时录入的实际需求后再启动该阶段，不作为首期隐含要求。

```text
浏览器 / PWA → 登录与 LifeOS API → 服务端笔记库副本
                                       ↕ 文件同步
                                各设备 Obsidian 笔记库
```

- 复用业务模型和校验规则，增加服务端存储适配层。
- 服务端文件仍为权威数据，数据库仅用于索引和缓存。
- API 写入校验身份、实体权限、版本和幂等键。
- PWA 增加本地草稿与离线队列，明确同步中、失败和冲突状态。
- 服务端写入与 Obsidian 外部编辑采用同一冲突策略。
- 可评估官方 Headless Sync；目前公开测试，部署前重新核对稳定性和条款。
- 同一服务端同步副本只运行一种 Sync 客户端。
- 服务端持有可读笔记，不能把整套 Web 架构宣称为服务端不可见的端到端加密。
- 账号、部署位置、备份、访问审计和密钥管理需要独立详细设计。
- 首期业务接口应便于扩展，但不提前建设空置的云服务。

## 11. 非功能要求

以下性能为验收目标，不代表当前已有测试结果。

| 编号 | 要求 | 验证方式 |
|---|---|---|
| N01 | 桌面与移动端核心录入可用 | 用户实际设备测试，移动布局无横向溢出 |
| N02 | 320px 及以上宽度支持核心页面 | 表单、导航、列表和详情检查 |
| N03 | 1 万个受管文件下索引不得阻塞持续操作 | 分批索引，可取消或反馈进度 |
| N04 | 索引完成后常用列表首屏目标 1 秒以内 | 指定设备与样本实测 |
| N05 | 普通单文件保存目标 1 秒以内 | 不含网络同步与大附件复制 |
| N06 | 长列表分页或虚拟化 | 1 万条交易样本滚动检查 |
| N07 | 核心操作可键盘访问，表单有标签 | 桌面键盘与移动触控测试 |
| N08 | 卸载插件后文件仍可读 | 使用原生编辑器读取全部实体样本 |
| N09 | 不覆盖未知属性和自由正文 | 外部编辑及冲突测试 |
| N10 | 索引损坏可重建且统计一致 | 删除缓存后重新计算对账 |

测试报告须记录设备、系统、Obsidian 版本、同步方式和样本规模；未达到性能目标时列明实际结果及限制。

## 13. 验收标准

### 13.1 P0 / P1 必须通过

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| A01 | 新用户配置目录 | 可以生成基础目录并创建日记和交易 |
| A02 | 同一天再次写日记 | 打开已有日记，不重复创建 |
| A03 | 记录 12.50 元支出 | 文件保存 1250 分，页面与月统计均为 12.50 元 |
| A04 | 同账户转账与同币种正常转账 | 前者阻止；后者不进入收支统计 |
| A05 | 跨月退款 | 按退款日抵减净支出，保留原交易关系 |
| A06 | 超额退款或删除被引用原支出 | 阻止并说明原因 |
| A07 | 重复点击保存与失败重试 | 仅生成一笔交易 |
| A08 | 手动修改正文和未知属性后保存表单 | 内容保留，无整文件覆盖 |
| A09 | 编辑期间另一入口修改文件 | 暂停争议写入，提供重新加载或副本 |
| A10 | 两台设备离线各新增不同交易 | 同步后两笔均保留，统计无重复 |
| A11 | 两台设备同时编辑同一条记录 | 按选定同步服务演练，双方内容可恢复 |
| A12 | 无法读取同步服务状态 | 不展示虚假的“已同步” |
| A13 | 删除、恢复及缓存重建 | 恢复内容完整，统计重新一致 |
| A14 | 非法 YAML、重复 ID、关联缺失 | 报告问题，不损坏原文件 |
| A15 | 手机创建、编辑、搜索和查看详情 | 核心流程可独立完成 |
| A16 | 从独立备份恢复 | 文件、附件和关系可读取，索引可重建 |
| A17 | 不同币种交易 | 分币种展示，不出现未经定义的合计 |
| A18 | 只填标题创建待办 | 进入收集箱，默认 not_started 与 medium，生成唯一 ID |
| A19 | 完成、重复完成、撤销完成与取消 | 时间与计数按规则变化，重复完成不刷新完成时间，取消不计为完成 |
| A20 | 今日与逾期待办跨天 | 原任务 ID 不变，不复制；逾期单独分组，每项只展示一次 |
| A21 | 两台设备同时修改待办状态 | 不静默覆盖，争议版本可恢复，完成计数不重复 |
| A22 | 手写正文 checkbox 与表单状态 | checkbox 原样保留，不被误识别为系统任务，YAML status 决定页面状态 |
| A23 | 项目关联 2 个完成、1 个未完成、1 个取消任务 | 进度为 2/3；移出任务后重新计算，无任务不显示 100% |
| A24 | 全部任务完成 | 项目不自动完成，用户按完成标准确认 |
| A25 | 存在未完成任务时结束项目 | 列出明细并处理保留、取消或移出，失败可重试且无重复写入 |
| A26 | 修改状态、取消、归档和重新打开项目 | 不自动改待办状态；重新打开恢复 in_progress、清空完成时间及管理标记 |
| A27 | 删除有引用的项目或在关闭项目新增待办 | 阻止直接操作并说明处理路径 |
| A28 | 非法计划日期与项目日期 | 待办计划日晚于截止日、项目目标日早于开始日均阻止保存 |
| A29 | 移动端待办与项目操作 | 可创建待办、完成及撤销、关联项目、查看进度和归档 |
| A30 | 当天完成任务及源笔记关联 | 日记页面可回看；源笔记缺失时提示但不删除任务 |
| A31 | 首页汇总多个模块进行中内容 | 仅展示已接入模块的 in_progress 项；未开始与已完成不显示，开始后移入，完成或改回未开始后移出；计数和集中查看一致 |
| A32 | 日记跨类型多选 | 切换类型保留已选，按 ID 去重；解除关联不删除原内容 |
| A33 | 日记中新建关联项 | 保存后自动关联并返回日记，既有多选项保留；取消不生成实体 |
| A34 | 项目多文件上传 | 逐项成功或失败可辨认，重试不覆盖原文件，列表信息完整 |
| A35 | 文件引用与多端访问 | 移出列表不删除共享文件，桌面手机可打开同步完成的文档 |
| A36 | 七类统一状态 | 新建、详情、筛选统一三状态；后续模块上线逐项验收，不以原型代替验证 |
| A37 | 卡片内容超出框架 | 卡片尺寸和标题不跳动，列表出现滚动条且末尾记录可访问，表单操作保持可见；手机无水平溢出 |

### 13.2 后续阶段必须通过

- 同一本书两次完成阅读：已读作品数与重读次数符合定义。
- 同一电影两次完整观看：作品数为 1，完整观看次数为 2。
- 剧集单集观看不被计为整部完成。
- 游戏未填时长不被解释为零时长。
- 取消演出不进入参加次数；票款仅通过交易计算一次。
- 旅行预算与实际支出分开，所有费用可进入交易明细核对。
- 标题和路径变化后 ID 关联仍有效，缺失双链明确提示。
- 从阅读记录创建知识笔记时来源可追溯。
- 附件在实际桌面、手机同步后均可打开。
- P2 模块接入后补验 A31–A33、A36 的完整七类集合和跨十类关联；P1 不虚构未实现模块的数据。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 同步竞争和冲突 | 内容覆盖、统计重复 | 独立记录文件、稳定 ID、版本检查、恢复演练 |
| 记账文件数量增加 | 索引和同步变慢 | 增量索引、分页、实际大样本验证 |
| 手动编辑破坏 schema | 字段失效 | 无损校验、问题列表、保留源文件 |
| 插件桌面实现不兼容手机 | 多端目标落空 | P0 即验证移动宿主，使用公开 API |
| 十个模块同时铺开 | 长期无法完成日常闭环 | P1 只做日记、记账及基础待办项目，后续分阶段扩展 |
| 待办状态多处维护 | 勾选与统计不一致 | YAML 状态唯一权威，首期不同步自由正文 checkbox |
| 项目批量操作部分失败 | 任务归属或状态不完整 | 展示逐项结果，记录可重试操作，执行后重新校验 |
| 多处保存同一金额或状态 | 数据不一致 | 明确权威字段，汇总只读计算 |
| Headless Sync 状态变化 | 网页接入不稳定 | 仅在 P4 评估，允许替换同步适配 |
| 把同步当备份 | 误删传播后难恢复 | 独立备份和恢复验收 |

## 17. DEV-001 实施契约补充

2026-10-08 冻结实施契约1.0：[架构](docs/architecture.md)、[数据规范](docs/data-schema.md)、[验收追踪](docs/test-plan.md)。本文仍为需求v1.3；契约版本、产品版本和数据schema版本独立。后续实现遵守下列明确口径，发生变化同步修订本文与契约。

- 十个界面模块对应十种存储类型；阅读/影视/游戏共用work，具体阅读/观看/游玩/演出参与存experience。首页七类进行中以档案与任务/项目为对象，演出参与经历不重复列为演出事项。
- 新建数据schema_version=1，ID使用不可变UUID v4。日期为YYYY-MM-DD字符串，时间含时区偏移；初始业务时区Asia/Shanghai，可配置，历史业务日期不自动重写。
- 记账中“分类”正式字段为category_id；账户与分类是稳定ID字典。金额正安全整数，以货币最小单位保存，按币种统计。P1退款限定原支出账户和币种；有退款引用时禁止修改原支出的金额、币种、账户和分类。未确认汇率不合并币种。
- 评分冻结为可选0–10，允许小数，缺失不默认为0。项目没有有效任务时进度未知；归档任务仍属项目工作量，取消任务排除。
- 未知属性保护其值与类型，未编辑正文保持原文；不承诺YAML空格/排序完全不变。完整内容版本变化暂停写入，不能仅依赖updated_at作为冲突判断。
- 项目附件默认单文件20MiB、可配置，实际同步限制由DEV-002确认；名称/大小/类型/导入时间通过可同步元信息展示。解除引用不物理删除文件，多文件失败逐项恢复。
- DEV-001完成只表示文档契约冻结。真实设备、插件适配、同步、备份、性能及A01–A37运行验收仍待后续任务实施。
