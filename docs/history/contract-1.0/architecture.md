# LifeOS 实施架构契约

契约版本：1.0；冻结日期：2026-10-08；状态：DEV-001 已冻结。
依据：[PRD v1.3](../PRD-v1.0.md)。配套：[数据契约](data-schema.md)、[验收计划](test-plan.md)。冻结表示后续实现必须遵守；调整须同步修改 PRD、契约和受影响验收项，记录原因，不表示产品已经实现。

## 1. 交付边界

首期是 Obsidian 社区插件内的 LifeOS 视图，桌面与手机共用业务模型。P1 完成日记、记账、待办、项目；P2 接入阅读、影视、游戏、演出、旅游及地点；P3 接入知识；P4 单独评估 Web/PWA。原型只用作交互参考。

采用 TypeScript、React 和 esbuild；具体依赖版本、最低 Obsidian 版本由 DEV-003 锁定并由真实宿主验证。禁止业务层依赖 Node、Electron、桌面绝对路径或浏览器本地存储作为业务权威。移动端公开 API 能力在 DEV-008 验证。

## 2. 分层与权威来源

| 层 | 目录 | 职责与依赖 |
|---|---|---|
| 界面 | `src/ui/` | 页面、表单、关联选择器、框内滚动；调用应用服务，不直接修改 Vault |
| 应用 | `src/services/` | 保存、关系、上传、项目关闭流程；调用领域与端口 |
| 领域 | `src/domain/` | 十类实体、金额、日期、状态、统计纯规则；不访问宿主、DOM、文件系统 |
| 端口 | `src/ports/` | NoteStore、AttachmentStore、OperationStore、Clock、IdGenerator 接口 |
| 宿主适配 | `src/adapters/obsidian/` | 公开 Vault/FileManager/Editor API、文件事件、路径边界、内容版本保护 |
| 查询 | `src/index/` | 可重建索引、反向关系、增量事件处理；仅从业务文件读取 |
| 设置 | `src/settings/` | 设备偏好与 Vault 内业务字典分开 |

Markdown、简单 YAML 属性、附件及系统业务配置是权威来源。缓存损坏可删除重建，不能反向覆盖文件。十个界面模块对应十种存储类型，阅读/影视/游戏共用 work，消费和参与记录使用 experience；不能按页面另建重复实体。

默认管理根目录是 Vault 内的 `LifeOS/`，可配置。模块目录依次为 `00_系统/`、`10_日记/`、`20_记账/`、`30_作品/`、`40_经历/`、`50_演出/`、`60_旅游/`、`70_地点/`、`80_知识/`、`81_待办/`、`82_项目/`、`90_附件/`、`99_回收与冲突/`。根目录不能是附件或回收目录；模块映射不得重叠。仅索引配置范围内的合法实体，回收、冲突和系统记录不参与业务统计。

## 3. 单文件保存与冲突

1. 打开记录时读取完整原文，保存不透明内容版本令牌；令牌必须代表完整文件内容，不能只用 updated_at 或文件修改时间。
2. 校验表单变更，只改所拥有字段。正文只有用户明确编辑时才修改；未知属性的值与类型必须保留。YAML 排版和键顺序不承诺逐字节不变。
3. 提交时在受保护的更新回调内比较当前内容与编辑基线；不一致则终止写入，返回 `conflict`。用户选择重新加载或保存带新 ID 的副本，不能静默覆盖。
4. 通过宿主适配器保护同宿主读改写；DEV-006 必须验证实际 API 与编码器满足上述条件。非法 YAML、未知 schema_version、重复 ID 记录只读并报告，不自动修复或清空。
5. 成功后返回实际保存版本并更新索引。保存按钮防连点不是幂等的唯一保障。

NoteStore 最低语义：`create(entity, operationId)`、`read(id)` 返回原文/实体/版本、`update(id, expectedVersion, patch, operationId)`、`trash(id, expectedVersion)`、`restore(id)`；失败区分 validation、conflict、not_found、io、unsupported_schema。端口实现不能把失败包装成成功。

官方建议修改时使用实时读取或 Vault.process，后者的同步回调防止宿主内读改写竞争；它不构成跨设备锁。[Vault 文档](https://docs.obsidian.md/Plugins/Vault)。官方推荐 Frontmatter 用 FileManager.processFrontMatter、活动编辑器正文用 Editor；若单独调用无法同时保障版本检查和正文保护，适配器使用 Vault.process 的受保护文本变更，并以无损和冲突测试证明选择。[插件检查清单](https://docs.obsidian.md/oo/plugin)。

## 4. 幂等与多文件流程

新建前生成实体 UUID 和操作 UUID。一次用户提交的失败重试沿用相同操作 ID、实体 ID 与请求内容；修改提交内容须启动新操作。已存在同 ID 且内容符合该请求则返回已有结果；不同内容则报冲突，禁止另写一份。

`00_系统/operations/<operation_id>.json` 保存最小可恢复日志：版本、操作类型、请求指纹、目标 ID、发起设备 ID、各步骤和失败原因。操作日志是可恢复业务状态，不是可随意丢弃的缓存。不得存用户凭据。外部设备尚未结束的日志不自动接管；需核对实际文件并显式恢复。同步服务可能仍产生冲突副本，不能宣称日志实现分布式互斥。

| 流程 | 顺序与失败恢复 |
|---|---|
| 新建日记关联项 | 保存目标 → 给日记附加 ID → 返回日记。附加失败保留已建实体和原选择，重试关系步骤；取消创建不生成目标 |
| 项目文件 | 检查路径/大小 → 逐项复制附件 → 写附件元信息 → 给项目附加路径。失败保留逐项结果；已复制未关联文件可恢复，重试不覆盖 |
| 项目完成 | 列出未完成任务 → 用户选保留/取消/移出 → 逐项受保护写入 → 重新查询与校验 → 最后完成项目。失败项目保持原状态，展示已经发生的变更，可继续恢复；不承诺跨文件回滚 |
| 删除/恢复 | 先校验引用限制 → 回收文件并记录原路径 → 重建受影响关系和统计。回收记录保留原 ID；恢复遇同 ID/路径冲突先处理，不覆盖 |

项目取消、归档只改项目；全部任务完成也不自动完成项目。删除被退款引用的原支出、被任务或其他实体引用的项目须先处理引用。普通缺失目标保留引用并提示，不能级联删除内容。

## 5. 附件、设置与路径

所有业务路径保存为 Vault 相对路径、正斜杠分隔。标准化后拒绝绝对路径、盘符、路径穿越及越出管理根目录；文件选择来源只能用于读取，不能成为持久引用。

项目附件复制到 `90_附件/项目/<project_id>/`；目标文件名加独立附件 UUID，保留扩展名，避免重名覆盖。默认单文件限制 20 MiB，可配置，DEV-002 按实际同步服务调整；限制检查基于真实字节数。列表展示原名称、大小、类型、导入时间和逐项结果。

`00_系统/attachments/<attachment_id>.json` 保存 schema_version、id、path、original_name、size_bytes、media_type、imported_at、operation_id。未知 MIME 用 application/octet-stream，不依赖跨端文件创建时间。项目 attachment_paths 是引用权威；元信息辅助显示。文件未同步到本设备时显示暂不可用；移出列表只解除引用。物理删除须明确操作、确认无其他引用，失败保持文件可恢复。

业务字典、时区、货币定义、目录映射保存在可同步的 `00_系统/`；UI 偏好和当前设备 ID 使用插件 loadData/saveData。业务字典不能只保存于某设备插件配置。根目录变更先预览验证再切换，不自动搬移已有文件。

## 6. 查询、状态与布局

索引按稳定 ID 定位，路径是可更新定位信息。文件新增/修改/删除/重命名触发增量校验；批量事件合并，全量扫描分批且可取消。重复 ID 两份均标记异常且不进入统计，不能随机选择一份。恢复完整性后重建。

首页进行中集合：task、project、work（book/movie/series/game）、performance、trip，要求 status=in_progress 且未取消、未归档、无冲突。参与 experience 不再重复列作演出事项。按 ID 去重，计数与集中查看共用查询。P1 只显示已上线模块，后续接入无需改变查询口径。

界面导航：首页/记录/回看/设置。每个卡片、列表、详情和弹窗具有受可用视口约束的框架；标题和操作区保持可见，内容区纵向滚动。尺寸随宿主空间适配，不把原型高度写死；320px 起无横向溢出，长文本换行，末条和键盘焦点可访问。状态切换不能只依赖拖拽。

## 7. 多端边界和冻结决策

只选一种 Vault 文件同步机制，由 DEV-002 确认，P1 不开发自有云端或上传队列。反馈分为本地已保存、同步状态未知、冲突/失败；读取不到真实状态就提示“同步状态请在 Obsidian 中查看”。同步不等于备份，DEV-009 必须演练独立备份恢复。

移动宿主没有桌面 Node/Electron 环境；模拟手机界面不能替代真实设备验收。[移动开发说明](https://docs.obsidian.md/Plugins/Getting%20started/Mobile%20development)。
